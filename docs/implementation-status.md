# 初回MVPの実装状況

更新日：2026-11-08

## 実装済み

- ページ内の「この求人を調べる」右クリックメニュー。
- 起動元タブのメインフレームから、本文・JSON-LDを取得。
- 職種・仕事内容・応募資格・企業名・勤務地・給与・雇用形態の抽出と根拠の保持。
- 求人票／判定保留／対象外の判定、企業名未特定の保留表示。
- 独立した確認画面、原抽出値と修正値の分離、再判定・リセット。
- 取得結果のID単位のセッション管理、確認画面を閉じた場合の削除。
- 元タブの移動・閉鎖・同URL再読み込み・権限不足のエラー処理。
- RA個別求人の企業名・募集職種のサイト別抽出（共有された要素構造に基づく初期対応）。
- RAの「求める能力・経験」を応募資格として取得し、勤務地を対応sectionに限定して配属先・転勤区画を除外。

## 実装していない範囲

外部企業調査、Google Sheets API連携、外部LLM API、採点・応募判断の自動化、OCR・PDF・別フレーム本文の取得。SpikeのGoogle検索保存機能は変更していない。

## 追加フェーズ：Ollama分析

- Ollamaを模擬したブラウザ結合テストで、手動実行・採用値の送信・根拠表示・未反映編集の防止・古い結果の表示・失敗時保持・再読み込みを確認した。
- PC上のOllamaに限定して、確認画面から手動で条件別評価表・優先順の確認事項を生成し、分析時点の採用情報を直接表示する機能を追加。
- 採用値と出所・条件・プロフィールを送信し、原抽出値と修正履歴をセッション内で維持する。根拠IDと参照箇所を照合し、未反映編集を防止する。失敗時は抽出情報を保持し、入力変更時は古い分析を明示。
- 既存の抽出処理と求人票の3区分判定は変更しない。
- 実Ollamaのgemma3:4bに架空の求人を送り、構造化結果の生成・検証成功を確認した。
- 利用者によるOrigin設定後の実求人分析成功を確認。今回の条件別評価は実Ollamaの4Bと共有抜粋6条件で確認した。全希望条件での実RA画面はリロード後に手動確認が必要。既存のOllama設定は変更していない。
- 詳細・テスト範囲は [local-llm-analysis.md](local-llm-analysis.md) を参照。

## 検証結果

- Node自動テスト51件（既存・RA関連36件＋分析関連15件）：成功。
- Playwright / Chromium 158.0.8127.18で7種類の合成ページの結合テスト：成功。
- 確認画面の表示、項目修正・再判定・リセット、再読み込み後の修正値保持、複数結果の分離、閉鎖時削除を確認。
- HTML風の入力を実行せず文字列として表示することを確認。RAの検証URLはリクエストを横取りしてローカルの再現HTMLで応答し、実際のRAサイトへ通信しない。
- デスクトップ幅・幅390pxのスクリーンショットを目視確認。

## 残る確認

利用者から2026-11-08に提供された実画面で、RAの企業名・職種・仕事内容の取得と求人票判定を1件確認した。企業名は修正なしで元の抽出値が採用されている。全文の網羅性・他求人の精度は未評価。

エージェントによるネイティブ右クリック操作の自動確認は未完了。専用ブラウザのWindows操作ツールが所有者照合エラーを返したため、UI操作を中止した履歴がある。これは利用者からの実画面による確認と区別する。

自動のブラウザ結合テストは、localhostとRA検証URL用のhost権限を付けた一時コピーで取得処理を呼び出している。製品Manifestによるネイティブメニュー起動の成功とは扱わない。`npm.cmd run test:native` でこの残りの確認を実行できる。

RAの企業名・職種・応募資格の見出し・勤務地の親sectionは利用者が共有したHTMLと画像に基づく。再現HTMLの本文・企業名・住所等は架空の値で、勤務地の住所欄の内部構造は合成である。今回追加した応募資格・勤務地の修正は、実ページでの再確認が必要。RA全体への対応完了とは扱わない。

実求人サイトでの網羅的な抽出精度は未評価。対象媒体の別の個別求人・一覧・一般ページで取得値と判定理由を確認し、媒体固有のDOMが必要な場合に追加対応する。以上の確認を終えるまでは仕様書の完了条件をすべて満たしたとは扱わない。
