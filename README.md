# 求人調査 MVP

開いているページで右クリックし、「この求人を調べる」から求人票の抽出・判定・確認を行うChrome拡張です。

個別求人の3区分判定、抽出値の確認・修正・再判定に加え、PC上のOllamaによる手動分析に対応しています。Google Sheets登録・外部企業調査・外部LLM APIは実装していません。APIキーやPythonサーバーは不要です。

`../spike/` はGoogle検索ページ保存の技術検証として独立して残しています。

## RAへの初期対応

`https://mypage.r-agent.com/joboffers/数値ID` の個別求人票では、共有いただいたHTMLと画像に基づく専用の抽出を行います。

- 企業名：`p` の `JobInformation_corpName__` で始まるクラス
- 募集職種：`h1` の `JobInformation_title__` で始まるクラス
- 応募資格：「求める能力・経験」のh3と`aria-labelledby`で対応するsection内の本文
- 勤務地：「勤務地」のh2と対応するsection内に限定し、「配属先」「転勤」の子sectionを除外

クラス名末尾の生成文字列やクラスの順序に依存しません。複数の異なる候補がある場合は専用抽出で決め打ちしません。別サイトや求人一覧のURLではこの処理を適用せず、従来の共通処理を使用します。

企業名・職種だけでは「求人票」と確定しません。仕事内容・給与・雇用形態などは共通の抽出・判定処理を使用します。応募資格・勤務地で見出しと本文の対応が壊れている場合、広い領域をまとめて取得せず、未取得と理由を表示します。

企業名・職種の取得と求人票判定は、利用者提供の実画面で1件確認しています。応募資格・勤務地の今回の修正は再現HTMLで検証しており、実ページでの再確認が必要です。勤務地内の住所欄の詳細な構造は未確認のため、関連情報をすべて住所だけに正規化する機能ではありません。テストではRAサイトへアクセスしません。

## Chromeへの読み込み

Chrome 116以降を対象とします。

1. Chromeで `chrome://extensions` を開きます。
2. 開発者モードを有効にし、「パッケージ化されていない拡張機能を読み込む」を選びます。
3. **このフォルダ内の `extension` フォルダ**を指定します。
   例：`D:\Dev\chrome-extension\job-research-mvp\extension`
4. 読み込み後に「求人調査 MVP — 求人票の確認」が表示されることを確認します。

`spike/extension` とは別の拡張です。今回はツールバーのポップアップを使わず、ページ内の右クリックを起点にします。

## 操作

1. HTTP(S)の求人詳細ページを開き、読み込みが完了するまで待ちます。
2. ページの本文や余白で右クリックし、「この求人を調べる」を選びます。
3. 新しく開く確認タブで、判定結果・理由・取得元・不足項目を確認します。
4. 必要なら企業名・職種・仕事内容・応募資格・勤務地・給与・雇用形態を編集し、「修正して再判定」を押します。
5. 修正項目には「利用者修正」と表示され、元の抽出値を展開して比較できます。「修正をリセット」で原抽出値に戻せます。

入力値を消して再判定すると、その項目は未取得になります。画面を閉じるとその結果は削除されます。ブラウザ終了・拡張の無効化／再読み込みでもセッション結果は失われます。

### 希望条件の管理（求人検索ツール）

- ツールバーの拡張アイコンを左クリックすると、希望条件の管理画面が専用タブで開きます（開いていればそのタブを前面に出します）。
- 入力が止まって約1秒後に `chrome.storage.local` へ自動保存し、保存中・保存済み・保存失敗を表示します。失敗しても入力は消さず、「もう一度保存する」で再試行できます。原文は分割・要約・補正しません（textareaの仕様で改行はLFにそろいます）。
- インポート／エクスポートはUTF-8のテキストファイルです。UTF-8として読めないファイルは拒否し、既存の内容を上書きする前に確認します。
- 求人の確認画面では、分析結果がない求人に限り、保存済みの希望条件を初期値として読み込みます。分析済みの求人はその分析時の条件を優先します。確認画面での変更は共通の希望条件に保存しません。「共通の希望条件を読み込む」で明示的に置き換えられます。
- 求人分析で使える希望条件は2,000文字までです。それを超える内容も保存はできますが、管理画面に注意を表示します。

## 判定

- **求人票**：表示中の主な求人に対応するJobPostingを確認、または職種・仕事内容と募集条件や応募導線を確認。
- **判定保留**：根拠不足、複数の構造化求人で主対象不明、本文と構造化データの相違等。
- **対象外**：求人一覧・検索結果、個別求人の根拠がない一般ページ等。

給与・勤務地の欠落だけでは除外しません。企業名が未特定でも求人票という区分は維持し、企業調査保留と表示します。すべての区分で、初回MVPは確認画面までで終了します。

判定はヒューリスティックで、採用情報の事実確認や求人の推薦・採点ではありません。関連求人のJSON-LDだけでは求人票と確定しません。募集企業名と求人媒体名を混同しないよう、雇用主のラベルまたはJobPostingのhiringOrganizationを参照します。

## 制約

- 本文抽出は見出し、定義リスト、表、一般的なラベル形式を対象とします。全求人媒体専用の対応ではありません。
- JSON-LDは単独オブジェクト・配列・`@graph`を対象とします。Microdata・RDFa、OCR、PDF、別フレーム内の本文には対応しません。
- 初回の表示一致確認には主なh1と仕事内容を使います。h1がないページや表現が大きく異なるページは保留になることがあります。
- 求人一覧や、主対象が特定できない複数JobPostingは、項目を入力しただけでは個別求人として確定しません。個別求人を開いて再取得してください。
- 本文と構造化データの企業名等が異なる場合、該当項目の修正値を使って再判定できます。修正した事実と元の根拠を保持します。
- Chrome内部ページ等の取得失敗は「対象外」の判定とは区別し、エラーで案内します。元ページが移動した場合も再取得が必要です。
- 同一ページ内で遅延表示される情報は、表示完了後に再取得してください。外部リンクや別ページの情報を補完取得しません。

## 権限・データ

本番Manifestの権限は `contextMenus`・`activeTab`・`scripting`・`storage` と、ローカルOllama通信用の `http://127.0.0.1/*` です。実際の分析API接続先はコードとCSPで `http://127.0.0.1:11434` に限定しています。求人サイトは右クリックしたページだけを読み取り、抽出した項目と短い根拠を `chrome.storage.session` に保持します。ページ全文・MHTML・閲覧履歴の恒久保存は行いません。

WebページとLLMの文字列は確認画面で文字列として表示し、HTMLとして実行しません。元ページ自身の通常通信を制御する機能ではありません。

## ローカルLLM分析

1. Ollamaを起動します。既存のローカルモデルを使い、拡張はモデルをダウンロードしません。
2. 確認画面で抽出内容を確認し、編集した場合は「修正して再判定」を押します。
3. 「Ollamaのモデル一覧を取得」を押し、モデルを選びます。導入済みなら `gemma3:4b` が初期選択です。
4. 希望条件を1行に1条件で入力し、「比較する条件を確認」で分割・分類を確認してから「ローカルLLMで分析」を押します。
5. 分析時点の採用情報・条件別評価表・優先順の確認事項を確認します。判定の根拠ID・出所・該当箇所も表示します。

初回はOllamaの `OLLAMA_ORIGINS` にこの拡張のOriginを追加する必要があります。403が返る場合は、Originの末尾にスラッシュがないかと、Ollamaの再起動を確認してください。設定手順は [ローカルLLM分析](docs/local-llm-analysis.md#接続許可の設定) を参照してください。Ollamaの設定や再起動は自動では行っていません。

分析するのは修正後に採用された7項目と希望条件です。求人URLやページ全体は送信しません。入力合計6,000文字まで、待機上限3分です。失敗しても抽出結果は残ります。入力変更後の古い分析結果には再実行が必要と表示します。

## 開発・テスト

Node.js 20以降を使用します。Windows PowerShellで `npm.ps1` が実行ポリシーにより拒否される場合も、以下の `npm.cmd` で実行できます。

```powershell
cd D:\Dev\chrome-extension\job-research-mvp
npm.cmd ci
npm.cmd test
```

ブラウザ結合テストは、専用Chromiumを用意して実行します。

```powershell
node node_modules/playwright/cli.js install chromium
npm.cmd run test:browser
npm.cmd run test:analysis
```

この自動テストは一時コピーにlocalhostとRA検証URL用のhost権限を付け、合成ページからの取得・画面表示・修正・リセット・セッション再表示・タブ間分離・画面を閉じた際の削除を検証します。RA検証URLのリクエストはすべて横取りし、ローカルの再現用HTMLで応答します。実際のRAサイトへは通信しません。製品のManifestと権限は変更しません。

**この自動テストだけでは、ネイティブの右クリック選択によるactiveTab権限の付与を確認できません。** 次の対話型テスト、または実際に読み込んだ拡張で確認します。

```powershell
npm.cmd run test:native
```

専用の検証ブラウザが開くので、サンプルページ内で右クリックし「この求人を調べる」を選びます。本番Manifestで取得・判定できればテストが成功し、結果表示後に検証ブラウザが閉じます。4分以内に選択しない場合は終了します。通常使用中のChromeプロファイルは使いません。

スクリーンショットとブラウザ検証結果は `test-results/` に出力し、Git管理対象外とします。

## 構成

- `extension/background.js`：右クリックメニュー・メッセージ受付・結果削除
- `extension/workflow.js`：起動元タブの検証・取得・セッション保存・再判定
- `extension/extract-page.js`：表示本文・JSON-LDからの抽出
- `extension/classify.js`：副作用のない判定・修正値の処理
- `extension/review.*`：確認・修正画面
- `tests/`：自動テスト・合成ページ・ブラウザ検証
- `docs/job-page-detection.md`：合意済み仕様
- `docs/implementation-status.md`：実装状況と検証の範囲

分析には採用値の出所（元ページ抽出／利用者修正）と分析時点の入力を保持します。採用値を求人原文の事実として保証せず、根拠ID・該当箇所・取得元項目を表示します。求人内の根拠不足は「要確認」、未実施の外部照合は「未調査」です。詳細は [条件別評価の仕様と検証範囲](docs/local-llm-analysis.md) を参照してください。
